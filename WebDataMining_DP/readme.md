### 二、必须掌握的三个核心概念（3天）
1. 什么是差分隐私（1天）

一句话：向数据中加入精心设计的噪声，使得攻击者无法判断某条记录是否在数据集中，但仍能获得有用的统计信息 。

核心参数是 ε（隐私预算）：

    ε 越小 → 噪声越大 → 隐私保护越强 → 数据可用性越低

    ε 越大 → 噪声越小 → 隐私保护越弱 → 数据可用性越高

你只需要理解：ε 控制隐私和效用之间的权衡。
2. 什么是本地差分隐私（LDP）（1天）

    关键区别：传统DP在服务器端加噪，LDP在用户端加噪后再上传。服务器永远看不到原始数据。
这正好对应Web搜索日志场景：用户在浏览器端对搜索行为加噪，服务器只能收到扰动后的数据。
3. 什么是频率估计（1天）

核心任务：服务器从扰动数据中估计哪些查询词最热门。

如果你有 n 个用户，每个用户对查询词 v 产生一个扰动报告，服务器统计后，用公式反推真实频率：

估计频率 = (扰动后计数 - n × q) / (p - q)

其中 p 和 q 是扰动参数，由 ε 决定。你不需要自己推导公式，用现成库即可。
### 三、四周执行计划
#### 第1周：跑通代码 + 理解原理

目标：让 OUE 算法跑起来，画出第一张隐私-效用曲线。

不要自己从头实现LDP协议，直接用 Python 现成库：

    pure-LDP：实现了 OUE、OLH、RAPPOR 等主流频率估计协议

multi-freq-ldpy：支持单维/多维频率估计

安装：pip install pure-ldp

第1-2天：生成模拟搜索日志。10000个用户、1000个查询词，查询词服从 Zipf 分布（少数词很热，大多数词很冷）。

第3-4天：调用 pure-LDP 的 OUE 客户端，对每个用户的查询做本地扰动，服务器端估计频率。对比真实频率和估计频率，计算 MAE 和 Top-50 重叠率。

第5-7天：跑不同 ε 值（0.5、1、2、4、8），画两条曲线：MAE vs ε、Top-50重叠率 vs ε。这两张图就是你论文的核心实验结果。

#### 第2周：补充对比实验 + 开始写作

第2-3天：用 pure-LDP 跑 OLH 和 RAPPOR，和 OUE 对比。三个协议、五个 ε 值，形成一张对比表。

第4-5天：写论文的引言和相关工作。引言按这个逻辑：Web搜索日志有价值 → 但收集会泄露隐私 → LDP可以解决 → 本文用OUE做热点挖掘并分析隐私-效用权衡。

第6-7天：写预备知识，包括 ε-LDP 定义和 OUE 的基本原理。OUE 的核心思想：用户把查询编码为 0/1 向量，然后按概率 p 和 q 随机翻转每一位 。

#### 第3周：完成论文初稿

第1-3天：写方法和实验部分。方法部分画一个系统框架图（用户→扰动→服务器→估计→Top-K），实验部分放所有结果表格和图。

第4-5天：写讨论和结论。讨论部分分析：ε=4 时 Top-50 重叠率已经很高，说明中等隐私预算即可实现较好的挖掘效果；ε<1 时噪声过大，效用急剧下降。

第6-7天：整理参考文献（15-20篇），检查格式。

第3-4天：预讲2次，控制在10分钟内。重点讲清楚：为什么需要LDP、OUE怎么工作、ε如何影响结果。

第5-7天：修改、查重、提交。

### 六、关键提示

关于“创新点”：课程论文不需要算法创新。你的贡献可以写：

    将LDP频率估计方法应用于Web搜索日志热点挖掘场景

    系统比较了OUE/OLH/RAPPOR在搜索日志上的隐私-效用表现

    量化了不同ε下Top-K挖掘效果的差异

关于代码：不要自己实现LDP协议。用 pure-LDP 或 multi-freq-ldpy，你只需要写数据生成、调用库函数、计算指标、画图。你的Java和Python基础足够应付。

关于时间：如果第2周发现时间不够，砍掉OLH和RAPPOR对比，只做OUE一个协议。一篇完整的OUE实验论文，质量远高于三个协议都只做一半。

关于数据：全部用模拟数据，不需要真实Web日志。模拟数据可以自由控制分布、规模、噪声水平，反而更容易做出清晰的实验结果。
